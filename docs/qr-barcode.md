# 二维码与条形码

2026-11-05。首页原「二维码」工具升级为「二维码 / 条形码」，沿用原工具 ID，原收藏和最近使用记录继续有效。编码、图片解析、相机扫码全部离线运行，复用已有 ZXing 依赖。

## 生成

二维码提供网址、文本、Wi-Fi、联系人、邮件、短信六种模板。网址校验完整的 HTTP / HTTPS 地址，文本保留原始空格和换行。Wi-Fi 支持 WPA / WPA2、WEP、无密码和隐藏网络，密码可显示 / 隐藏，正确转义名称与密码中的特殊字符；无密码网络不会编码隐藏的旧密码。联系人使用 vCard 3.0；邮件与短信对中文、换行、加号、百分号及查询参数保留字符进行编码。

二维码可选 512 / 1024 / 2048 px 边长、L / M / Q / H 容错等级，以及墨黑、深蓝、墨绿三种深色配白底，保留四模块静区。内容超出容量时显示原因，并提示缩短内容或降低容错等级。

条形码支持以下七种生成格式：

| 码制 | 输入规则 |
| --- | --- |
| Code 128 | 1–80 个可打印 ASCII 字符，保留首尾空格 |
| EAN-13 | 12 位数字自动补校验位，或校验完整 13 位 |
| EAN-8 | 7 位数字自动补校验位，或校验完整 8 位 |
| UPC-A | 11 位数字自动补校验位，或校验完整 12 位；保留前导零 |
| Code 39 | 1–80 位大写字母、数字、空格和 `- . $ / + %` |
| ITF | 2–80 位数字，长度须为偶数 |
| Codabar | 2–80 位数字或 `- $ : / . +`，自动添加 A 起止符 |

每种格式均可一键填入示例，输入无效时给出具体规则。条形码可选 512 / 1024 / 2048 px 目标宽度，黑白输出，可选择是否显示下方编号；内容过密时按完整模块自动加宽，左右保留静区。

点击生成后在后台编码。预览显示实际像素尺寸，可全屏查看、双指缩放至 6 倍和拖动，也可保存 PNG、分享或复制编码内容。修改内容或参数后会提示重新生成，并禁用旧预览的保存和分享，避免导出与当前输入不符的图片。PNG 编码与文件写入也在后台执行。

## 解析

图片导入和普通相机扫码统一支持 QR Code、Code 128、Code 39、Code 93、EAN-13、EAN-8、UPC-A、UPC-E、ITF 和 Codabar。一次返回一个码；多码图片需要裁出目标后分别读取。

支持横向、纵向、倒置及反色图像。大图片先降采样，透明像素按白底合成；完整、规整的高密度二维码在常规定位失败后尝试直接提取模块，仍经过二维码纠错校验，以改善迁移码等截图的识别。解析结果显示实际识别的码制、内容类型、结构化详情及原始文本，可以复制、转为二维码；在支持生成的条形码格式下，还可按原码制重新生成。UPC-A 与以 0 开头的 EAN-13 存在等价表示，以识别器实际返回的码制为准。Codabar 识别文本不包含起止符，再生成时补上 A 起止符。

相机保留原有的对焦、补光灯、缩放、权限处理和帧释放机制。身份验证器的相机和图片入口继续只识别二维码，不接受条形码，并保留原有的 TOTP / Google 批量迁移校验流程。生成内容和解析结果不自动写入本地数据库。
